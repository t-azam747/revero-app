## Further risks requiring evidence, not established bugs

- Walkthrough schema changes need real-source accuracy evaluation; valid timestamps/evidence IDs are not independent factual verification. Existing caption checks do not prove video understanding.
- CDN access experiment checks DNS addresses then HTTPX resolves again; it is not a DNS-pinned network boundary. Automatic video downloading is deferred; do not promote this experimental helper into an ingestion fetcher.
- Invalid video timestamps/headers, unbounded overall library growth and free-tier sensitive-data use need operations/terms review before a production trial.
- Sender-candidate bootstrap stores scoped IDs for signed unregistered senders, while rejecting intake/reply. Decide candidate retention and strict-owner interpretation in M2; do not silently expand owner scope.
- Backend lock versions match locally but clean Linux dependency/browser/system-library installation remains unverified. Existing fresh-schema tests do not substitute for representative historical DB upgrades.

## Safe reproduction

From repository root:

```sh
PYTHONPATH=backend backend/.venv/bin/python docs/m0/reproduce-probes.py
```

The script mutates **temporary** databases only and prints schema/constraint outcomes. It does not initialize or change the personal DB, read secret values, or make provider calls. Expected output includes helper `(1,15000,delete)`, main-equivalent `(0,10000)`, `old view remains stale: True`, and `legacy outbox rejects summary after saved: True`.

For source-only findings, the named function/call path is the reproduction and the future behavioral acceptance check is explicit in the table. No speculative failure is labelled reproduced. Fix ordering for M1 should begin D04/D02/D01 with backup-aware representative upgrades, then D03/D09/D13; M3/M4/M5 behavior changes require their own later approval.
